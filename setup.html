💬 Ollama — Autoregressive LLMs & Vision Models CHECKING
Required. Ollama is the core inference engine that runs autoregressive language models (LLaMA 3.x, Qwen 3, Mistral, DeepSeek R1, Gemma 3) and vision-language models (LLaVA, Qwen-VL, MiniCPM-V) using llama.cpp under the hood. It serves the chat, reasoning, and /imagine prompt workflows.
RequirementDetails
Default Port11434
Health EndpointGET /api/tags
Min Disk~5 GB (base) + model sizes (2–70 GB each)
GPU RecommendedApple Silicon (Metal), NVIDIA CUDA, AMD ROCm
  1. Install via Homebrew (recommended): 
    brew install ollama
  2. Or download the macOS installer from ollama.com/download
  3. Start the daemon: 
    ollama serve
  4. Pull a model to test: 
    # Recommended starter models
ollama pull llama3.2:3b       # Fast 3B text model
ollama pull qwen3:8b          # Strong 8B reasoning model
ollama pull llava:7b          # Vision-language model
  1. One-line install (official script): 
    curl -fsSL https://ollama.com/install.sh | sh
  2. The installer sets up ollama as a systemd service. Start it: 
    sudo systemctl start ollama
sudo systemctl enable ollama  # Auto-start on boot
  3. Pull a model: ollama pull llama3.2:3b
For NVIDIA GPU acceleration, ensure CUDA drivers and nvidia-container-toolkit are installed.
  1. Download the Windows installer from ollama.com/download
  2. Run the .exe installer and follow the wizard
  3. Ollama runs as a system tray application. It starts the daemon automatically on launch.
  4. Open a terminal and pull a model: ollama pull llama3.2:3b
docker run -d --name ollama -p 11434:11434 \
  -v ollama_models:/root/.ollama \
  ollama/ollama:latest
For NVIDIA GPU passthrough, add --gpus all to the command.
🎨 Stable Diffusion WebUI — Image Generation CHECKING
Optional. Enables the Image Studio workspace for text-to-image and image-to-image generation via AUTOMATIC1111 or Forge WebUI. Also powers the /imagine inline command in chat. Download checkpoints from CivitAI via the Model Hub.
RequirementDetails
Default Port7860
Health EndpointGET /sdapi/v1/sd-models
Critical Flag--api (must be passed at launch)
Min VRAM4 GB (SD 1.5), 6 GB (SDXL), 8–12 GB (FLUX)
Checkpoint Pathmodels/Stable-diffusion/
  1. Clone the repository: 
    git clone https://github.com/AUTOMATIC1111/stable-diffusion-webui.git
cd stable-diffusion-webui
  2. Download a checkpoint (e.g., from CivitAI) and place it in models/Stable-diffusion/
  3. Launch with API mode enabled: 
    # macOS / Linux
./webui.sh --api

# Windows
webui-user.bat  # Edit COMMANDLINE_ARGS to include --api
The --api flag is mandatory. Without it, the REST API endpoints (/sdapi/v1/txt2img) are disabled and the Image Studio will not function.
  1. Clone Forge (optimized fork with better memory management): 
    git clone https://github.com/lllyasviel/stable-diffusion-webui-forge.git
cd stable-diffusion-webui-forge
  2. Place checkpoints in models/Stable-diffusion/
  3. Launch: ./webui.sh --api
Forge typically uses 30-40% less VRAM than AUTOMATIC1111 for the same models.
# AUTOMATIC1111 via Docker (NVIDIA GPU required)
docker run -d --name sd-webui --gpus all \
  -p 7860:7860 \
  -v sd-models:/app/models \
  ghcr.io/neggles/sd-webui-docker:latest \
  --api --listen
GGUF Diffusion Models (FLUX, SDXL): Use the HuggingFace tab in the Model Hub to download .gguf quantized diffusion weights. Place them in models/Stable-diffusion/ for SD WebUI or models/diffusion_models/ for ComfyUI.
🔮 ComfyUI — Node-Based Diffusion Workflows CHECKING
Optional. ComfyUI is a node-based visual workflow editor for diffusion models (FLUX, SDXL, SD 3, ControlNet, IP-Adapter). Health monitoring is integrated; use ComfyUI's own browser UI at :8188 for workflow editing. Download GGUF-quantized diffusion weights from the HuggingFace Hub tab.
RequirementDetails
Default Port8188
Health EndpointGET /system_stats
GGUF Model Pathmodels/diffusion_models/ or models/unet/
Min VRAM4 GB (Q4), 6 GB (Q8), 12+ GB (FP16)
  1. Clone the repository: 
    git clone https://github.com/comfyanonymous/ComfyUI.git
cd ComfyUI
pip install -r requirements.txt
  2. Launch ComfyUI: 
    python main.py --listen 0.0.0.0 --port 8188
  3. Open http://localhost:8188 in your browser to access the node editor
  1. Install the ComfyUI-GGUF extension: 
    cd ComfyUI/custom_nodes
git clone https://github.com/city96/ComfyUI-GGUF.git
pip install -r ComfyUI-GGUF/requirements.txt
  2. Download GGUF weights from HuggingFace (use the Model Hub → 🎨 Text-to-Image tab): 
    # Example: FLUX.1-schnell Q4_0 (~5 GB, runs on 6 GB VRAM)
wget -c "https://huggingface.co/city96/FLUX.1-schnell-gguf/resolve/main/flux1-schnell-Q4_0.gguf" \
  -O ComfyUI/models/diffusion_models/flux1-schnell-Q4_0.gguf
  3. Restart ComfyUI. The GGUF loader node will appear in the node editor.
GGUF quantizations (Q4, Q5, Q8) reduce FLUX.1 from ~24 GB FP16 to 5–12 GB, fitting on consumer GPUs.
docker run -d --name comfyui --gpus all \
  -p 8188:8188 \
  -v comfy-models:/app/models \
  ghcr.io/ai-dock/comfyui:latest
🎙️ Whisper ASR — Speech-to-Text Transcription CHECKING
Optional. Enables the Audio Lab transcription workspace and the microphone dictation button in the chat composer. Supports whisper.cpp (C++, fastest) and faster-whisper (Python, CTranslate2). The workstation auto-detects which API format your server uses.
RequirementDetails
Default Port8178
Health EndpointGET /health
API FormatsPOST /inference (whisper.cpp) or POST /v1/audio/transcriptions (OpenAI-compatible)
Model Sizestiny (75 MB), base (142 MB), small (466 MB), medium (1.5 GB), large-v3 (3 GB)
  1. Clone and build whisper.cpp: 
    git clone https://github.com/ggerganov/whisper.cpp.git
cd whisper.cpp
make -j
  2. Download a model: 
    bash models/download-ggml-model.sh base
  3. Start the HTTP server: 
    ./server -m models/ggml-base.bin --port 8178
On Apple Silicon, whisper.cpp uses Core ML / Metal acceleration automatically.
  1. Install faster-whisper: 
    pip install faster-whisper
# Or with GPU support:
pip install faster-whisper[gpu]
  2. Run as an OpenAI-compatible server: 
    pip install whisper-asr-webservice
uvicorn app.webservice:app --host 0.0.0.0 --port 8178
docker run -d --name whisper -p 8178:9000 \
  -e ASR_MODEL=base \
  -e ASR_ENGINE=faster_whisper \
  onerahmet/openai-whisper-asr-webservice:latest
Change ASR_MODEL to small, medium, or large-v3 for higher accuracy (requires more RAM/VRAM).
🔊 Piper TTS — Neural Text-to-Speech CHECKING
Optional. Enables local neural text-to-speech for the Audio Lab synthesizer card and the "Read Aloud" button on assistant messages. If Piper is offline, the workstation automatically falls back to the browser's built-in Web Speech API (no installation required for basic TTS).
RequirementDetails
Default Port5000
Health EndpointGET /api/voices
FallbackBrowser Web Speech API (always available, lower quality)
Voice Models~15–100 MB each, 25+ languages available
  1. Install Piper TTS: 
    pip install piper-tts piper-http-server
  2. Download a voice model: 
    # Browse voices: https://rhasspy.github.io/piper-samples/
piper --download-voice en_US-lessac-medium
  3. Start the HTTP server: 
    piper-http-server --port 5000
docker run -d --name piper -p 5000:10200 \
  rhasspy/wyoming-piper:latest \
  --voice en_US-lessac-medium
Change --voice to any Piper voice ID. Browse all voices at piper-samples.
🐳 Docker Compose — Turnkey Deployment ALL-IN-ONE
Deploy the gateway, Ollama, Whisper, and Piper in a single command. SD WebUI and ComfyUI require separate GPU-enabled containers or native installation. 
docker compose up -d
The docker-compose.yml in the repository root defines: liw-gateway (:3300), liw-ollama (:11434), liw-whisper (:8178), liw-piper (:5000). For GPU passthrough on NVIDIA, uncomment the deploy.resources section in the compose file.
